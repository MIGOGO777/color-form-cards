# Kuuga 主控入口配置示例

本文件是供合并到实际入口的片段，不替代现有身份、权限、项目和安全规则，也不自动生效。下方相对路径以本仓库根为例；采用时换成实际可达路径。

- 主 Agent 默认白色；普通任务直接处理，颜色不绑定模型或思考强度。
- 独立处理有净收益时，先读取 docs/dispatch-protocol.md，再建议数量、颜色、具体模型、思考强度、范围、验收及成本。用户批准对应工作单后才派发；讨论颜色或发现 Skill 不等于批准。
- 主控使用下表摘要选择，不为选色加载四份正文。获准叶子使用无主会话历史继承的独立上下文，只读对应一个 Skill，向主控回执，不继续调用 Agent、不写项目 Save、不换色。
- 无历史继承不保证无系统或插件注入；实际隔离需另行验证。颜色判断和建议不代替高风险动作批准。

| 颜色 | 主要缺口与交付 | Skill 入口 |
|---|---|---|
| 绿 | 有价值的新路径、改变的假设和最小验证 | skills/kuuga-green-explore/SKILL.md |
| 蓝 | 关键命题成立到哪里、决定性证据和缺口 | skills/kuuga-blue-evidence/SKILL.md |
| 红 | 明确或条件判断、依据和反转条件 | skills/kuuga-red-decide/SKILL.md |
| 紫 | 批准范围内的实现、修复与验证 | skills/kuuga-purple-build/SKILL.md |

没有独立收益时白色直接处理；不默认按绿→蓝→红→紫流转。下一颜色另建工作单，按调度协议取得批准。Skill发现、正文读取、隔离派发和实际验收分别记录。
